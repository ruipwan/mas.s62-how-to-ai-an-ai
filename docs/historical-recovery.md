# Recovering an interrupted classic episode

`codetest.recovery.run_recovery(source_run, new_output, live_client_factory, *, usage_callback=None, recovery_metadata=None)` reconstructs a stopped episode from its saved decisions and tool results. `validate_recovery(source_run, new_output)` performs the same reconstruction and stops at the first missing action without constructing a live client.

Recovery requires a fresh output directory and an immutable historical run. The current implementation supports classic single-publication Commit0 runs and scripted fixtures. It rejects unsupported histories, changed inference source or task inputs, incomplete decision receipts, and mismatching saved state. It verifies completed candidate sources, publication trees and commit identities, scratchpad contents, and the partial logical state. Only commands from a lost active workspace are executed again in the isolated task sandbox. Their recorded outputs must match except for elapsed timing. Completed candidate checks are reused from the frozen history.

The live factory is called only after all historical checks pass. Its context includes the configuration, event callback, output directory, interrupted request identity, and verification report. The caller owns credentials and budget accounting. Historical API events are references and do not reserve or settle ledger charges again. A caller must carry prior confirmed estimates and unconfirmed full reservations into the authorized condition budget. Metrics and video phase costs cover the complete logical trajectory, including referenced history, so old and recovered metrics must not be summed as separate experiments.

This is historical-action recovery, not proof of byte-identical original model input. The original harness did not record full request hashes or active workspace checkpoints. The recovered run records that limitation and its source hashes. Existing source artifacts remain unchanged. The separate transport options in `recovery-transport.md` provide bounded timeout retries after the caller explicitly enables them.
